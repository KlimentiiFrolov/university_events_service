# План: проверка ролей после добавления слоя представления

## Текущее состояние

Роли вынесены в отдельную таблицу `roles` (`api_service/src/models/roles.py`):
модель `Role` с полем `name`, типизированным как `Mapped[RoleName]` через
`sqlalchemy.Enum(RoleName, native_enum=False, ...)` — хранится как обычный
`VARCHAR`, без нативного enum-типа Postgres. `User.role_id` — обязательный
(`NOT NULL`) внешний ключ на `roles.id`: у пользователя ровно одна роль,
многие-ко-многим не делали — в проекте всего два значения
(`participant`, `organizer`), и они взаимоисключающие.

Слоя представления (роутеров, `FastAPI()`-приложения) пока не существует —
`api_service/main.py` содержит только smoke-тест настроек. Соответственно,
проверок доступа по ролям в коде тоже пока нет.

## Как будет устроена проверка ролей

Два независимых уровня, каждый решает свою задачу:

### 1. Проверка роли на уровне эндпоинта (грубая)

FastAPI-зависимость вида `require_role(RoleName.ORGANIZER)`, читающая
`current_user.role.name`, где `current_user` приходит из будущей зависимости
`get_current_user` (JWT). Зависимости для JWT (`pyjwt`, `bcrypt`) уже есть в
`pyproject.toml`, но пока не используются — нет ни аутентификации, ни
роутеров.

Отвечает на вопрос: «пользователю с такой ролью вообще разрешено дергать
этот эндпоинт?».

### 2. Проверка владения объектом (тонкая)

Остаётся в сервисном слое — по образцу уже существующего
`EventService._ensure_owner` (`api_service/src/services/events.py`), который
кидает `ForbiddenError`, если `event.created_by_id != organizer_id`.

Отвечает на вопрос: «этому конкретному пользователю разрешено менять именно
эту запись?» — это бизнес-правило, а не забота роутинга, поэтому в
FastAPI-зависимость его выносить не стоит.

## Чего сознательно не делаем

Отдельную таблицу permissions/scopes (roles ↔ permissions many-to-many) не
заводим — с двумя ролями это оверинжиниринг. Возвращаться к этому решению
стоит, только если ролей станет больше или потребуется более гранулярный
контроль доступа (не «роль → эндпоинт», а «конкретное разрешение →
эндпоинт»).

## Когда делать

Разбирать при добавлении слоя представления: сначала `get_current_user`
(JWT-декодирование + подгрузка `User.role`), затем `require_role` как
переиспользуемая FastAPI-зависимость на нужных роутерах.
